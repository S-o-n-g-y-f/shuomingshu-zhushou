# 说明书助手

把药品说明书的小字变大、读出来，并把多张说明书汇总成一张用药清单。
**只帮您看清原文，不提供用药建议。**

## 现在能做什么

1. **两个录入入口**：
   - **家人代录**：子女照药盒写药名、规格，照医生说的原话写用法。填的时候实时做文字防错核对，再走核对与卡片。
   - **自己拍照**：拍说明书或药盒、粘贴原文 → 核对字段 → 大字卡片 → 语音朗读 → 保存图片。
2. **本地防错**：把录入的药名、规格与本地目录比对，抓抄错的字（如 0.25g 写成 2.5g）。内置的是一小份演示样本；可从国家药监局、国家医保编码库等公开数据整理 CSV 导入（格式：`药名,规格,厂家,批准文号`），只保存在浏览器本地。**只核对文字，不判断药的真伪、好坏、能不能一起吃；查不到不代表药有问题。**
3. **服药人信息（可跳过）**：首次打开可选填昵称、性别、年龄、体重（每项可不填，整页可跳过）。说明书常按人群给多套用法（成人 / 儿童 / 按体重），工具按年龄**从原文里选出对应人群的段落**展示，并提示"勿转给其他人群使用"；匹配不上就保持原样黄条，绝不猜方案。**不按体重计算剂量**——mg/kg 写法照抄原文，请与医生给的量核对。信息只存本机。
4. **用药清单**：把多张卡片加进清单，自动按服药时间排序，并提示时间被排在一起的安排。清单可整张导出成图片。
5. **数据只在本地**：清单与导入目录都存在浏览器 localStorage，图片用 Canvas 在浏览器里生成，不上传任何服务器。

## 运行

在线版：GitHub Pages 直接打开（见仓库描述 / Devpost 项目页）。

本地运行（零依赖，不需要 npm install）：

```bash
python -m http.server 8765 --bind 127.0.0.1
```

浏览器打开 `http://127.0.0.1:8765`。纯静态 HTML/CSS/JS，数据只存浏览器本地。

## 全量评测（102 份真实说明书）

`test/evaluate.cjs` 把 `samples/` 下 102 份真实说明书文字版喂进抽取层，对照**独立于抽取层的金标准**统计（药名取人工命名、次数用独立读取器、严重警示扫不良反应+注意事项两段）：

| 指标 | 结果 |
|---|---|
| 药名提取准确 | 100%（102/102） |
| 规格 / 用量原文出处可追溯 | 100%（102/102） |
| 明确次数的说明书，时间示例换算正确 | 100%（55/55） |
| 含严重警示说明书的关键词定位召回 | 100%（69/69） |
| **剂量 / 时间严重错误** | **0（0/102）** |
| 不确定写法诚实挂"请核对" | 35 份 |
| 需人工确认比例 | 34.3% |
| 按需服药（PRN）正确归入"按需服用" | 100%（3/3，人工标注金标准） |

"需人工确认"的构成（35 份）：16 份原文按病种/人群给了多套用法（不假装选其中一种）、14 份为区间或个体化剂量写法（一日 2-3 次、遵医嘱调整，不猜测）、5 份原文要求睡前服但常规示例时间是白天（矛盾必须人工核对）。3 份按需药（对乙酰氨基酚、硝酸甘油、萘普生）已从"无法换算"细分为「按需服药」类别——没有固定时间表不是"看不懂"，而是这类药的正确用法本身。

评测中发现并修复三处真 bug：① 严重警示只扫不良反应段，漏掉了写在注意事项里的警示（如阿莫西林"抽搐"）——已扩到两段；② 出处校验依赖截断到 200 字的展示字段，把原段后半部分的用量（如美托洛尔 50-100mg）误判为"无出处"——已改为完整原文兜底；③ 段落切分把正文里的交叉引用（如"请参照【用法用量】"）误当成新标题，截断了原段导致用量抓空——改为只认行首标题。另修正两处评测尺子：规格无唯一写法（0.1% = 10ml:10mg），硬指标改为原文出处可追溯；药名同理，文件名简写与说明书带盐基/商品名的完整通用名（依那普利片 vs 马来酸依那普利片（依苏））按归一化互相包含判定。

评测明细与统计见 `docs/evaluation.json`（明细不含说明书原文，可公开；`samples/` 原文目录不入公开仓库）。作品内的"我们测过"卡片展示核心数字。

时段词保护：原文写"早晨/睡前/随餐/饭前/饭后"等服药时机时，规则会单独保留并显示在卡片上，不会被时间示例吞掉。若原文要求睡前服、而换算出的时间落在白天，强制挂黄条提示核对（如普伐他汀、孟鲁司特等 4 份）；"饭前或饭后"这类二选一写法按原文合并展示，不提示成两个时段都要做到。

已知诚实局限：① 102 份是网上公开的说明书文字版，未覆盖药盒照片 OCR；② 区间频次（"一日1-2次""每日2-3次"）、"每12小时1次"、多适应症不同剂量一律挂黄条请用户自行核对，不猜测、不计入准确率；③ 规格写法没有唯一标准（0.1% = 10ml:10mg），文件名写法匹配率 92.2% 仅供参考，硬指标是原文出处可追溯率 100%；④ 抽取准确不等于用药正确，本工具始终不提供任何用药建议。

## 安全边界（不可突破）

- 这不是电子说明书，不是医疗器械，不是药物工具。
- 不提供剂量建议、不做药物相互作用判断、不判断能否同服、不提示禁忌。
- 清单里的"冲突"**只是时间和名称层面的观察**（同一时间、间隔过近、疑似重复、时间缺失），全部需要用户核对纸质说明书或咨询医生药师。
- 禁止把药品颜色、形状、外观写入任何卡片或清单——外观不能作为识别依据；家人代录填外观会被拦下。
- 防错目录只比对药名与规格文字；未收录、规格不符都只提示"请核对"，绝不说药不存在、有问题、不能吃。
- 所有输出固定带免责声明。

## 演示数据

`src/samples.js` 中的三份样张全部是**虚构药品与虚构文本**，仅用于演示抽取流程，不含任何真实用药信息。

## 让它真正能用还缺什么

- 拍照自动 OCR（当前需手动粘贴文字，这是老人独立使用的最大障碍）
- 家人协同分享（子女远程帮父母核对）
- 真实的适老化可用性测试
